# 00｜从零开始与运行路线

[全部阶段](../../README.md) · [下一篇｜准备并打包](../p01_prepare/01_准备并打包.md)

Windows 的 WSL Ubuntu 准备 Docker 归档并用 CPU 启动 OpenDM，Mac 通过 Tailscale 连接推理服务，运行 Agent 和 MuJoCo。联调通过后，再将归档导入 GPU 主机。 [启动推理和连接方式](../p02_inference/02_启动推理服务.md)

## 先看顺序

在项目根目录运行阶段 00，检查项目结构和 `MANIFEST.sha256` 记录的交付文件，再预览各阶段的命令。两条命令都只需 Python 标准库。

```bash
python3 dm05_workflow/p00_pipeline/00_02_run_pipeline.py --from-stage 0
python3 dm05_workflow/p00_pipeline/00_02_run_pipeline.py --dry-run
```

已有可用的 DM0.5 服务时，从第 03 步开始。模型和归档可通过配置放在移动硬盘上。

## 选择执行方式

可以直接运行各篇里的编号脚本，也可以在对应机器用总入口执行当前阶段。下面是在 WSL Ubuntu 执行阶段 01 的命令。

```bash
python3 dm05_workflow/p00_pipeline/00_02_run_pipeline.py --from-stage 1 --to-stage 1
```

当前 CPU 推理按第 02 步的 Tailscale 小节启动。阶段 02 和 03 都会在前台提供服务，保持终端运行，在另一台机器或另一个终端继续下一步。

阶段 03 先检查 Python 环境、依赖和实际使用的 Agent YAML。在 Linux 上使用 DOS-W1 时，选择 `--from-stage 3 --dos-w1`，总入口会等机械臂服务就绪后再启动 Agent。可以追加 `--dry-run` 预览这一分支。[DOS-W1 真机步骤](../../docs/dos_w1_setup_zh.md)

## 配置和产物

| 位置 | 用途 |
| --- | --- |
| `configs/standard.json` | 准备目录、镜像归档、Agent YAML、固定任务开关和联调记录的位置 |
| `configs/deployment.local.json` | 需要按机器调整路径时，复制标准配置到这个文件，并通过 `--config` 指定 |
| `agent/config/opendm.local.yaml` | Mac 的推理服务地址、机器人和网页设置 |
| `outputs/integration.json` | 第 04 步写出的联调记录 |

工作流 JSON 内的相对路径以项目根目录为准。第 03 步可用 `--agent-config` 覆盖本次启动的 YAML。第 04 步继续读取工作流 JSON 的 `agent_config`。 [标准配置](../../configs/standard.json) · [Python 执行顺序](../../README.md#python-执行顺序)
